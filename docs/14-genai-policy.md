# How this project uses generative AI

The project applies NLnet's policy on the use of generative artificial intelligence for NLnet-funded projects, in force since 8 December 2025 in its version 1.1 of 26 January 2026, and it will follow the revision NLnet has announced, which removes exceptions for new projects.

Code in this repository is written by its human contributors. A contribution generated with a language model is not accepted unless the commit names the model and version and explains how it was used, in which case the maintainers review it and may still decline it. Work generated purely by a model is not eligible as paid work under the grant and is declined. Contributors remain accountable for the correctness, originality and licensing of what they submit and must be able to explain every design and code decision they made.

For material other than code the policy asks for a general description of how generative AI is used, and this file is that description. The maintainers used Claude Fable 5.1 on 4 October 2026 to draft the initial documentation under `docs/`, the README, the contributing guide and the security policy from their own working notes; they reviewed those files, corrected them and keep them, and the facts in them cite their sources. Later non-code uses, such as drafting documentation, translating or summarising issues, are allowed as long as this file keeps describing them. The signal specification in `spec/` is written and frozen by people; a language model may proofread it but never defines a rule or a threshold.

Where generated content is allowed it is marked at the place it appears, in a note in the file or in the commit message. The project's application to NLnet disclosed the use of generative AI in its preparation together with a prompt provenance log naming the model, the dates and times, the prompts and the unedited outputs, as the policy requires.

A grantee must not present a model's work as their own, and the value of this project rests on rules and evidence that people can explain and defend to the maintainers of the packages that appear in its data set.
